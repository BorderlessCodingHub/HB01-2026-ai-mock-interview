# Hone — Engineering Analysis & PWA Readiness

**Date:** 2026-11-06 · **Scope:** `main` @ `50b77f9` (619 commits) · **Benchmark:** Career Forge v2 (`career-forge-v2` @ `9e91e22`)

Hone is a solid hackathon-grown product with a **well-structured backend** and a
**strong spec culture**, but it lags Career Forge on **delivery discipline,
frontend quality gates, observability and doc freshness** — and it has **one
critical security hole** that must be fixed before any "level up" work,
PWA included.

## 3. Findings in detail

### 3.1 CRITICAL — forged JWT = full account takeover

`backend/src/modules/auth/adapters/borderless-access-token-parser.ts`:

```ts
/** Parses Borderless Bearer access tokens without signature verification. */
const decoded = jwt.decode(token);   // no verify
```

`BorderlessTokenResolver` routes **any** three-segment token to this parser, then
`UserSyncService` upserts the user from the claims. Consequences:

- Anyone can craft `{"sub":"<victim externalId>","email":"<victim email>"}` and read/delete the victim's resumes (PII), interviews and study data.
- Tokens without `exp` never expire.
- Inventing new `sub` values creates unlimited users → **bypasses per-user token cap and session quotas** → unbounded OpenAI/AssemblyAI spend.

The comment in `frontend/src/lib/auth/auth.ts` explains the origin: JWT tokens
skip the Worker → Railway `/internal/borderless-sessions` hop "that currently
returns 403". The workaround removed authentication.

**Status:** fixed with option 1 on branch `fix/auth-signed-hone-jwt` — see AD-025 in `STATE.md`.

**Fix options (pick one):**

1. **Hone becomes the issuer (Career Forge ADR-008 pattern — recommended).** Borderless sign-in is a server-side credential check only; the backend (not the Next worker) calls Borderless, discards its token, and mints a **Hone-signed JWT** (`HS256` with `JWT_SECRET`, `exp`, `jti` for revocation). Verify with `jwt.verify`. Bonus: removes the Redis opaque-session store and the internal endpoint.
2. **Always register server-side.** Drop the JWT branch; every token goes through `/internal/borderless-sessions` (fix the 403 — it's a Cloudflare/WAF rule on `/internal/*`, or move the call to a non-`/internal` path with the shared secret).
3. **Verify against Borderless.** On first sight of a token, call a Borderless profile endpoint with it and cache the result in Redis for its TTL.

Also: compare `X-Internal-Auth-Secret` with `crypto.timingSafeEqual` (done in the same branch).

### 3.2 Frontend has no quality gate

- `frontend/package.json` has **no `test` script and no vitest** — `display-turns.test.ts` and `format-topic-angle.test.ts` never run.
- CI (`.github/workflows/`) only covers `backend/`. Frontend lint/type-check/build are not enforced on PRs.
- No browser E2E (Career Forge's Gate B uses Playwright for the demo flows).
- Biggest components are 450–660 lines (`practice/page.tsx` 662, `review-session-chat.tsx` 564, `interview-chat.tsx` 473) — extract hooks (`useInterviewStream`, `useReviewSession`) to make them testable.

**Fix:** add vitest + RTL, a `frontend-ci.yml` (lint, `check-types`, `test`, `build:cloudflare`), and a Playwright smoke for login → upload → practice → feedback.

### 3.3 Post-merge-only integration tests

`backend-integration-e2e.yml` runs on `push: main` + manual dispatch. A broken
repository or E2E flow is discovered **after** it's merged and deployed. Run it on
`pull_request` (it's already 30-min-capped and containerized).

### 3.4 Delivery & deployment

| | Hone | Career Forge |
|---|---|---|
| Tracker | Not linked — commit messages carry no issue key | Linear `LABS01-XX`, one issue = one branch = one PR |
| Branching | `dev` → `main` merges producing duplicated commits (`e8fcc0e`/`f3a7c66`, `956a5a9`/`3c2e978`) | Branch per issue, squash, 200–500 LOC target |
| Merge gate | Backend lint/types/unit on PR | Triple gate A (review) + B (UI) + C (`agent-verify`) |
| Deploy | API: Railway; FE: manual `wrangler deploy` ("trigger redeploy" commits) | `deploy.yml` auto-deploy on `main`, stack smoke in CI |
| Post-merge | — | `/end-task` checklist updates STATUS/ROADMAP |
| Smoke | — | `make smoke`, `stack-smoke` against prod compose |

**Fix:** adopt the Labs workflow: Linear issues (`LABS01` team, Hone project), branch `LABS01-XX-slug`, squash-merge PRs straight to `main` (retire `dev` or make it a protected integration branch with squash only), Cloudflare Workers Builds or a `deploy-frontend.yml` with `wrangler deploy` on `main`.

### 3.5 Observability

- Backend logs via `console.*`; no Sentry on API, worker or frontend.
- No LangSmith (or equivalent) tracing — prompt regressions, latency and token spend per graph run are invisible. Career Forge traces every `GraphRun` and has `cost-gate`, `golden-run`/`golden-check` scripts.
- PostHog covers product analytics only.

**Fix:** Sentry (Next + Express + worker), `LANGSMITH_TRACING=true` + project per env (LangChain JS picks it up automatically), structured logger (pino) with request id.

### 3.6 Documentation drift

- `README.md` is two READMEs concatenated; says frontend is on **Vercel** (it's Cloudflare/OpenNext), lists "JWT + refresh token" (refresh is gone; `hone_refresh_token` is only cleared), refers to `Backend/` casing.
- `.specs/project/ROADMAP.md` milestones M1–M4 are all `[ ]` though shipped.
- `STATE.md` repeatedly says **"commits deferred" / "UAT pending"** — work lands in specs but not in reviewed commits.
- Root `tasks.md` (40 KB, Portuguese) describes the original Better-T-Stack / Turborepo plan (`apps/server`, `packages/*`) — no longer the layout. Archive it.
- No `CLAUDE.md` / `AGENTS.md` for agent sessions (Career Forge's is the template).

### 3.7 Minor

- Swagger UI + `/api-docs.json` exposed publicly in production — gate behind `NODE_ENV !== "production"` or auth.
- `README` / env mention `TOKEN_LIMIT_*` correctly, but `.env.example` requires `ASSEMBLYAI_API_KEY` and full R2 creds even for local dev — add local defaults (MinIO) or make STT optional to lower onboarding friction.
- SSE parser (`sse-stream.ts`) reads only the first `data:` line per event — fine for JSON payloads today, but fragile.
- `frontend` has both `bun.lock` and `package-lock.json`; keep one.

## 5. PWA plan

### 5.1 Constraints specific to Hone

- **basePath `/ai-mock-interview`** in prod (none locally). Manifest `start_url`/`scope`/`id` and SW registration scope must include it.
- **Cloudflare Workers via OpenNext**: `public/` is served from the `ASSETS` binding with `run_worker_first: true`; headers come from `public/_headers`.
- **Next 16 builds with Turbopack by default** — `next-pwa` is dead and `@serwist/next` needs webpack. Prefer a **hand-written SW** (the official Next.js PWA guide approach) or `@serwist/turbopack` once evaluated.
- **API is cross-origin** (Railway) and interviews are **SSE streams**; STT uploads audio. The SW must never cache or buffer these.
- **Auth token in localStorage**: iOS standalone PWAs have storage isolated from Safari → users sign in again once after installing (acceptable; document it).
- **Mic in standalone**: `getUserMedia` works in iOS standalone (≥13.4); Safari records `audio/mp4` — backend already accepts any `audio/*`.

### 5.2 Phase 1 — Installable (≈1–2 days)

1. `src/app/manifest.ts` (Next metadata route):
   ```ts
   const base = process.env.NEXT_BASE_PATH ?? "";
   export default function manifest(): MetadataRoute.Manifest {
     return {
       id: `${base}/dashboard`,
       name: "Hone — AI Mock Interview",
       short_name: "Hone",
       start_url: `${base}/dashboard`,
       scope: `${base}/`,
       display: "standalone",
       background_color: "#ffffff",   // paper-white token
       theme_color: "#ffffff",
       icons: [
         { src: `${base}/icons/icon-192.png`, sizes: "192x192", type: "image/png" },
         { src: `${base}/icons/icon-512.png`, sizes: "512x512", type: "image/png" },
         { src: `${base}/icons/maskable-512.png`, sizes: "512x512", type: "image/png", purpose: "maskable" },
       ],
       shortcuts: [{ name: "New practice", url: `${base}/practice/new` }],
     };
   }
   ```
2. `layout.tsx`: `export const viewport = { themeColor: "#ffffff", viewportFit: "cover" }` and `metadata.appleWebApp = { capable: true, title: "Hone", statusBarStyle: "default" }`; fix `lang` and the title.
3. Safe-area padding on the mobile top bar and chat composer: `pt-[env(safe-area-inset-top)]`, `pb-[env(safe-area-inset-bottom)]`.
4. Icons: 192, 512, maskable 512 (safe zone), apple-touch already present (`app/apple-icon.png`).
5. Minimal `public/sw.js` + registration in a client component (`navigator.serviceWorker.register(`${base}/sw.js`, { scope: `${base}/` })`).
6. `public/_headers`:
   ```
   /sw.js
     Cache-Control: no-cache
     Service-Worker-Allowed: /ai-mock-interview/
   /manifest.webmanifest
     Cache-Control: public, max-age=3600
   ```
7. Install UX: capture `beforeinstallprompt` (Chromium) → "Install Hone" button in sidebar; iOS → one-time hint "Share → Add to Home Screen". Track with PostHog (`pwa_install_prompted`, `pwa_installed`, `display-mode: standalone` as a super property).

### 5.3 Phase 2 — Resilient offline shell (≈2–3 days)

SW strategy:

| Request | Strategy |
|---|---|
| `/_next/static/*`, fonts, icons | Cache-first (immutable, versioned) |
| App route navigations (`/dashboard`, `/practice`, `/study`…) | Network-first, fallback to cached shell, then `/offline` page |
| Cross-origin API (Railway), `/api/auth/*`, anything `text/event-stream`, `POST`/`DELETE` | **Network-only — do not intercept** |
| Landing (`/`) | Stale-while-revalidate |

- Add an `/offline` route ("You're offline — interviews need a connection; your history is below").
- Persist TanStack Query cache (`@tanstack/query-async-storage-persister` + IndexedDB) for **read-only** history: sessions, feedback, review items, weak answers. Practice/Study start buttons disabled with a clear offline banner (`navigator.onLine` + `online/offline` events).
- SW update flow: `skipWaiting` only on user confirm ("New version available — Reload") to avoid swapping JS mid-interview.
- Guard the in-progress interview: if the SSE drops (tab backgrounded on mobile / network flap), show "Connection lost — Resume" using the existing persisted turns (quick task 006) rather than a dead chat.

### 5.4 Phase 3 — Re-engagement (optional, ≈3–5 days)

- **Web Push** (Android + iOS ≥16.4 installed PWAs): natural triggers already exist as BullMQ jobs — "Your feedback and study backlog are ready", "Your session quota refilled", spaced-repetition reminders for review items. Needs VAPID keys, `PushSubscription` table, a `notifications` module and a worker job.
- App badging (`navigator.setAppBadge(count)`) for pending review items.
- Share target to accept a resume PDF from the OS share sheet (Android).

### 5.5 Acceptance checklist

- Chrome DevTools → Application → Manifest: installable, no warnings, on both `localhost:3001` and Labs basePath.
- Installs on Android Chrome and iOS Safari; opens standalone to `/dashboard`.
- Full interview incl. mic/STT works in standalone on iOS and Android.
- SSE streaming identical with SW active (no buffering); auth sign-in/out works.
- Airplane mode: app opens, history visible, start actions disabled with copy.
- New deploy → update prompt appears; never reloads mid-interview.
- Playwright: manifest served, SW registers, offline route renders.
